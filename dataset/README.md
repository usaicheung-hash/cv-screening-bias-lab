# CV Screening Bias Lab: synthetic data

The data behind the [CV Screening Bias Lab](https://huggingface.co/spaces/edwardwww/cv-screening-bias-lab)
Space, a teaching demo for the IS5113 *AI Ethics* group project at City University of Hong Kong
(Part 1, Topic 1: *Algorithmic Bias in Hiring Platforms*). Code: [GitHub](https://github.com/usaicheung-hash/cv-screening-bias-lab).

**Everything here is synthetic.** No real person, applicant or company is in this data. It is for teaching and
auditing practice only, and must not be used to train a real hiring system or to optimise a CV against a screener.

## Files

| Config | Rows | What it is |
|---|---|---|
| `hiring_history` | 6,000 | Simulated past applicants and the (biased) human hiring decisions used in Step 3 of the demo |
| `cv_variants` | 80 | The 4 Hong Kong job ads and the CV copies that differ in one detail (name, graduation year, career break, disability) |
| `llm_scores` | 177 | The saved scores and reasons from the AI recruiter (Qwen/Qwen2.5-72B-Instruct, 3 runs per CV) shown in Steps 2 and 4 |

## `hiring_history`: how it was generated

Generated by `history_sim.simulate(n=6000, gender_bias=1.0, age_bias=1.0, seed=7)` with NumPy's
`default_rng(7)`, so the same code always gives the same rows. The app does not store this data; it
re-creates it in memory each time it starts.

| Column | Meaning |
|---|---|
| `applicant_id` | 1 to 6000 |
| `gender` | Female or Male, 50/50 at random |
| `age_band` | `40+` or `Under 40` (age drawn uniformly from 22 to 60) |
| `skill_test` | Job skill test, Normal(60, 15), clipped to 0 to 100. Same distribution for every group |
| `years_experience` | min(age − 22, 25) × Uniform(0.4, 1.0) |
| `education_level` | 0 diploma (30%), 1 degree (50%), 2 master (20%) |
| `career_gap` | 1 if the CV shows a career break. Probability 55% for women, 5% for men (caregiving). Not job-relevant |
| `grad_year` | 2026 − (age − 22) ± 1. Reveals age |
| `truly_qualified` | 1 for the top 40% by merit, where merit = 0.06·(skill − 60) + 0.12·min(experience, 10) + 0.5·education + noise. Uses only job-relevant features |
| `hired_historically` | 1 for the top 40% by *biased* score = merit − 1.0·female − 1.0·over40 + noise. This is the label a company would train on |

**The bias mechanism.** Women and over-40s are just as qualified as everyone else (`truly_qualified` is about 40%
for every group), but past recruiters marked them down, so they were hired far less often:

| Group | Career gap | Truly qualified | Hired historically |
|---|---|---|---|
| Female | 54.8% | 39.5% | 24.8% |
| Male | 4.7% | 40.5% | 55.3% |
| 40+ | | 47.4% | 32.7% |
| Under 40 | | 31.8% | 48.1% |

In the demo, a "blind" logistic regression is trained on `hired_historically` using only `skill_test`,
`years_experience`, `education_level`, `career_gap` and `grad_year` (no gender, no age). It still learns the
bias, because `career_gap` stands in for gender and `grad_year` stands in for age (the proxy problem, as alleged
in *Mobley v. Workday*).

## `cv_variants` and `llm_scores`

Each test starts from one strong CV for the job and changes **one** detail. `test` is `name` (10 names from
different backgrounds and genders), `age`, `career` or `disability`; `baseline` is an average-quality CV used as a
reference line. In `llm_scores`, `prompt` is `normal` or `with fairness instruction` (Step 4). The scores come from
a single model on a few runs, so they are illustrative, not a scientific audit.
